# javascript-racingcar-precourse

우아한 테크코스 2주차 과제 : 자동자 경주 게임(Racing Car Game)

## ✨ 기능 목록 (Feature List)

### 1. 입력 기능

- 경주할 자동차 이름을 입력받는다.

  - "경주할 자동차 이름을 입력하세요.(이름은 쉼표(,) 기준으로 구분)" 문자열을 출력한다.
  - 사용자로부터 입력을 받는다.
    - **[예외처리1]** 문자열이 아닌 다른 타입으로 입력받을 경우(숫자, 불린 등)
    - **[예외처리2]** 입력받은 문자열에 콤마(,)가 포함되지 않은 경우
    - **[예외처리3]** 빈 문자열을 입력받았을 경우
  - 이름은 쉼표(`,`)로 구분하여 저장한다.
  - 각 자동차 이름은 5자 이하로 제한한다.
    - **[예외처리4]** 입력한 자동차의 개수가 1개일 경우
    - **[예외처리5]** 입력한 자동차의 이름이 5자가 초과되었거나 이름이 없을 경우
    - **[예외처리6]** 이름이 중복된 경우

- "시도할 횟수는 몇 회인가요?" 문자열을 출력하고, 시도할 횟수를 입력받는다.
  - **[예외처리7]** 입력받은 시도 횟수가 숫자값이 아니거나 음수일 경우

### 2. 게임 진행 기능

- 입력받은 횟수만큼 자동차 경주를 진행한다.
- 매 시도마다 각 자동차는 무작위 값에 따라 전진 여부가 결정된다.
  - 0~9까지 랜덤값을 받고, 4 이상일때만 전진하도록 한다
- 매 시도 후 각 자동차의 전진 상태를 출력한다.

### 3. 우승자 판별 및 출력 기능

- 모든 시도가 끝난 후, 가장 많이 전진한 자동차를 우승자로 판별한다.(분기)
  - 우승자는 한 명일 경우
  - 공동 우승자일 경우 쉼표(`,`)로 구분하여 함께 출력한다.

### 4. 테스트 기능

- 각 기능별 유효성 검증을 위한 테스트 코드를 작성한다.
- `Jest`를 사용하여 기능들이 정상적으로 동작하는지 확인한다.

### 📌 신경 쓴 부분

**1. App.js 간소화를 위한 구조 개선 노력**

이번 2주차 과제에서는 1주차 과제와 다른 방식으로 코드를 작성하고자 했습니다.

1주차 과제 때는 코드를 App.js에 모두 작성했었습니다. 말 그대로 파일 구조라는 게 없이 코드를 작성했던 것입니다.
그러다 보니 가독성이 떨어지는 느낌이 들었습니다.

그래서 이번 과제에서는 App.js를 최대한 간소화하고, 기능별로 파일을 분리하는 방향으로 코드를 작성했습니다.
처음에는 기존 방식대로 App.js에 코드를 완성한 뒤, 어떻게 분리하면 좋을지 고민했습니다.

**2. MVC 구조로 작성한 점**

MVC(Model–View–Controller) 구조를 참고해 각 역할을 나누는 연습을 했습니다.

    Model: 데이터나 상태를 관리하는 부분

    View: 화면에 표시되는 부분

    Controller: 사용자의 입력을 받아 Model과 View를 연결하는 부분

예를 들어, 자동차 정보를 클래스로 정의해 Model 폴더에 두고, 이를 화면에 출력하는 기능은 View에서 담당하도록 했습니다. 그리고 Controller가 사용자의 입력을 받아 Model의 데이터를 갱신하고, 그 결과를 View에 전달하는 구조로 설계했습니다.
이 구조를 참고하기 위해 아래의 블로그를 참고했습니다.

    ➡️ 참고자료: https://pozafly.github.io/javascript/javascript-mvc/

MVC 구조를 적용하면서 단순히 “코드를 보기 쉽게 만드는 것”뿐 아니라, 각 부분의 역할을 명확히 분리하는 것의 중요성을 체감했습니다. 예를 들어, 나중에 기능을 추가하거나 디자인을 바꿀 때 Model이나 Controller를 수정할 필요 없이 View만 변경하면 된다는 점이 인상적이었습니다. 이러한 구조 덕분에 코드가 훨씬 유연하고 유지보수가 쉬워졌습니다.

**3. 브랜치 분리 작업 (메인 / 리팩토링 / 테스트)**

작업을 체계적으로 관리하기 위해 **메인**, **리팩토링**, **테스트 코드 작성**용 브랜치를 각각 나누어 개발했습니다.

이렇게 분리한 이유는 리팩토링 전후의 코드를 쉽게 비교하기 위해서입니다. **MVC 구조 적용**과 **테스트 코드 작성**이 저에게 새로운 시도였습니다. 그래서 어떤 점을 고민해서 변경했는지, 기존 기능 코드를 모두 넣었는지 확인하고자 브랜치를 분리했습니다.

**4. 명령형 프로그래밍과 선언형 프로그래밍 적용**

javascript의 고차함수(map)를 활용해 최대한 선언형 프로그래밍 방식으로 코드를 작성하고자 했습니다.
자바스크립트를 공부하면서 명령형 프로그래밍과 선언형 프로그래밍의 차이를 배우게 되었고, 이번 기회에 그 내용을 실제 코드에 적용해보고 싶었습니다.

### 📌 배운 점

**1. Jest를 이용한 테스트 코드 작성을 통해 TDD 방식의 중요성을 체감함**

이번 과제에서는 Jest를 활용해 테스트 코드를 작성하면서 **TDD(Test-Driven Development)**의 중요성을 느꼈습니다. 기존에는 “요구사항 분석 → 설계 → 개발 → 테스트”의 순서로 코드를 작성했는데, 코드를 완성한 뒤 테스트 코드를 작성하다 보니 여러 문제점을 발견하게 되었습니다.

예를 들어, 시도 횟수 입력 검증 로직을 처음에는 **숫자가 아닐 경우만** 처리했지만, 테스트를 작성하면서 **음수 입력에 대한 예외 처리**도 필요하다는 점을 깨달았습니다.

다음 주차 과제에서는 TDD 방식으로 코드를 작성해야겠다고 다짐했습니다.

## ✅ 프로그래밍 요구사항 체크리스트

### 환경 및 실행 조건

- [ ] Node.js `22.19.0` 버전에서 실행 가능해야 한다.
- [ ] 외부 라이브러리를 사용하지 않는다.
- [ ] 프로그램 종료 시 `process.exit()`를 호출하지 않는다.

---

### 코드 스타일 가이드

- [ ] **Javascript Style Guide**를 따른다.
- [ ] **영문 이외의 언어**를 코드 내에서 사용하지 않는다.
- [ ] 클래스, 메서드, 함수 이름에 **특수문자**를 사용하지 않는다.
  - 예시: ❌ `function $handle()` → ✅ `function handle()`
- [ ] 상수명은 **SNAKE_CASE**로 작성한다.
  - 예시: `const FIREFOX`
- [ ] **indent depth(들여쓰기)**는 최대 2까지만 허용한다. (3 이상 금지)
- [ ] **3항 연산자(`?:`)**를 사용하지 않는다.
- [ ] 함수(또는 메서드)는 **한 가지 일만 하도록 작게 분리**한다.

---

### 테스트 및 검증

- [ ] `Jest`를 이용하여 구현한 기능 목록이 정상적으로 동작하는지 테스트한다.

---

### 필수 API 사용

- [ ] `@woowacourse/mission-utils` 라이브러리를 사용한다.
  - [ ] 랜덤 값 생성 시 `Random.pickNumberInRange()`를 활용한다.
